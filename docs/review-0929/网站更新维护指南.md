# YI KAI 网站更新维护指南

2026 年 9 月 29 日更新

**只更新 Works 作品时，请直接使用[中文作品更新助手](https://www.yikaistudio.com/works-editor)，按[长辈版操作说明](../works-upload/操作说明.md)独立完成。** 图片和资料会合成一个文件，上传到 GitHub 的 `content/works-updates` 即可自动发布。

下文的“交给 Codex”流程用于 Memories、About、WIP 等其他内容或复杂调整。

## 网站实际怎样更新

本次读取了 GitHub 部署记录，并检查了域名的实际响应：

- [Boxxelf/yikaiart](https://github.com/Boxxelf/yikaiart) 的 `main` 保存网站源代码。
- `main` 已连接 Vercel 的正式发布。源码提交到 `main` 后，Vercel 自动构建网站。
- 公开地址是 [yikaistudio.com](https://yikaistudio.com/)，会转向 [www.yikaistudio.com](https://www.yikaistudio.com/)。
- GitHub Pages 另有 `gh-pages` 分支，但它不是当前域名实际使用的服务。本次也同步该分支作为静态发布版本。
- 不需要再配置一套 GitHub Actions 发布流程，也不要改域名或 DNS。先前仅根据 Pages 设置推断域名由 Pages 提供服务，现已更正。

**正式发布以域名实际显示的新内容为准，不只看 GitHub 上传成功。** 单独上传图片仍不足以展示新作品，还要补上对应的作品资料。

## 每次更新，你只做三步

### 1. 准备一个有日期的文件夹

例如 `2026-10-15 网站更新`。放入原图，复制本目录的 [更新资料模板.txt](更新资料模板.txt)，填写所需内容。保留原文件，不必自己压缩；未知的年份或姓名留空。

| 类型 | 提供什么 | 显示位置 |
| --- | --- | --- |
| 新作品 | 图片、作品名、系列、材料、尺寸及单位；年份可选 | Works 对应系列 |
| 替换照片 | 新图片、现有作品名或网页链接、需要更改的信息 | 原作品页面，保留链接 |
| Studio 照片 | 图片、显示顺序、简短介绍 | About 的 In the studio 区域 |
| WIP / 短文 | 日期、标题、图片、正文或几句说明；可关联作品 | 首次需在 About 建立创作记录模板 |
| 历史合影 | 图片、年份、地点、人物及活动说明 | Memories |
| 履历 | 类别、年份、机构名称、城市 | About |

尺寸请明确「高 × 宽」和单位。WIP 不必写长文，一张图片加几句说明即可。

### 2. 交给 Codex，查看预览

复制这段话，并附上文件夹：

> 根据文件夹和说明更新 YI KAI 网站。先取得 Boxxelf/yikaiart 的最新 main，保留已有链接和远程修改。新增作品进入对应系列；Studio 照片放在 About 内，不单独建立 Studio 页面。先给我电脑和手机预览，核对图片、标题、年份、材料、尺寸与顺序，暂不发布。

你只需核对图片是否对应、文字是否正确、人物有无被裁切，以及手机是否好浏览。需要修改时直接说明，不必找代码。

### 3. 确认后发布

确认预览后回复：

> 这版确认，请提交到 Boxxelf/yikaiart 的 main，等待 Vercel 正式部署成功，并检查 yikaistudio.com 和 www.yikaistudio.com 确实是最新版。同步 gh-pages 静态版本，给我正式链接和本次提交记录。

提交 `main` 会触发正式更新，所以确认预览前，应保留在本地或独立分支。发布后自己打开正式地址检查一次，保留本次更新文件夹与提交链接。

## WIP 和 Blog 以后怎样加入

四张 Studio 照片已放入 About。以后建议在同一页照片下增加「Studio notes」入口，每条记录包括日期、标题、封面、正文及附图。WIP 和短文共用列表，不再增加独立 Studio 导航。

这个创作记录模板和可视化编辑后台目前都没有实现；第一次添加 WIP / Blog 时需先完成它们的内容结构。建好后仍使用相同的「图片＋说明」更新流程。以后如果更新频繁，可再增加「上传图片、填资料、保存草稿、发布」的表单后台。

## 如果发布后发现错误

把正式页面链接和需要修改的地方发给 Codex。小错误直接修正；需要恢复旧版时，根据上一次正常提交建立回退提交，再由 Vercel 发布。不要删除 GitHub 仓库或强制覆盖提交历史。GitHub 源码和自己的原始图片文件夹都应保留。

## 给技术维护者的文件地图

- Home：`/`；Works 档案：`/works`；旧 `/works?view=archive` 仍可用。
- 作品：`src/content/works.json`、`src/content/collections.ts`；图片：`public/art/`。
- About Studio：`src/content/studio.ts`、`src/components/StudioGallery.tsx`；图片：`public/studio/`。
- Memories 图注：`src/content/memories.json`；图片：`public/memories/`。
- About 生平及履历：`src/content/about.ts`、`biography.json`、`artist-profile.ts`。
- 发布前运行 `npm run build`，检查浏览器交互、移动布局、完整图片与旧链接。
- 作品数量与系列数量已自动计算，日常新增不用改代码。`src/content/works.json` 保留原始目录；`content/works-updates/*.json` 保存逐件更新；构建时生成 `src/content/works.generated.json` 和图片。旧 `prepare:art` 是全量导入，不应用来直接覆盖已经修订的目录。
- `dist` 是生成的网站。`main` 保存源码，`gh-pages` 保存静态产物。域名根路径使用 `/`，保留 `CNAME` 中的 `yikaistudio.com`。
- `docs/review-0929/` 中的清单和早期设计方案用于审核，不要放入公开网站的 `public` 或 `dist`。
- 本地原来的 `yikaiart-main` 文件夹没有 `.git`；发布使用独立克隆目录。下次应重新从 GitHub 获取最新源码，不凭旧下载文件夹覆盖远程。

公开参考：[Vercel 的 GitHub 集成](https://vercel.com/docs/git/vercel-for-github)、[GitHub Pages 发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。
